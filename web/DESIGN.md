# Biz360 SME ERP — Frontend Design System

The web app is a deliberate **sibling of the Safaricom Daraja developer portal**:
confident Safaricom green, classical corporate spacing, quiet neutrals, and line
icons. It is a working financial console, not a marketing site — green is a
precision accent, never a wash.

## Principles

1. **Calm by default, green for emphasis.** White surfaces, `ink` neutrals, and
   one brand green reserved for primary actions, active state, and key figures.
2. **Generous, classical spacing.** 6/8-point rhythm; 24px card padding; roomy
   page gutters (`max-w-[1400px]`, `px-4 sm:px-6`).
3. **Numbers are first-class.** Money is always tabular, right-aligned, two
   decimals, with the currency symbol. Never compute money in the UI.
4. **One source of truth for state.** Every status uses the shared `status.ts`
   maps so a "Paid" invoice looks the same everywhere.
5. **Accessible by construction.** Semantic landmarks, labelled controls,
   visible focus rings, `aria-*` on stateful widgets, colour never the only cue.

## Typography

- Headings: **Plus Jakarta Sans** (`font-sans`), 600/700, tight tracking.
- Body/UI: **Inter** (`font-body`), 400/500.
- Eyebrows: `.eyebrow` — 12px, 600, uppercase, `0.08em` tracking, brand green.
- Money and quantities: `tabular-nums` everywhere they appear in tables.

## Layout

- **Top navigation** — sticky `h-16`, white with blur, logo left, primary nav
  centre-left, notifications + user menu right. Active link: `brand-deep` text
  with a 2px green underline.
- **Hero band** — `rounded-2xl` green gradient (`brand-deep → brand →
  brand-hover`) with soft radial highlights. Used sparingly: dashboard welcome,
  auth aside.
- **Dashboard shell** — `DashboardShell` renders `TopNav`, a max-width main, and
  the footer; a left drawer handles mobile navigation.
- **Auth** — split screen. Green gradient aside (brand story) + white form card.
- **Footer** — quiet, single row, useful links.

All primitives live in `src/components/ui/` and are re-exported from
`index.ts`.

## Icons & charts

- **Icons:** `lucide-react` line icons only, `h-4 w-4` inline / `h-5 w-5` in
  badges. No filled or duotone sets.
- **Charts:** Recharts, brand-green primary series, neutral grid lines, no
  chartjunk. (Used where a trend clarifies — otherwise prefer tables.)

## Forms

React Hook Form + Zod. Rules:

- Validate on submit; show field errors under the control and a form-level error
  banner for API failures.
- Money inputs are `inputMode="decimal"` with a 2-decimal pattern; they submit
  **strings**.
- Financial mutations pass an `Idempotency-Key` (see `SECURITY.md`).

## Empty, loading, error states

Every list has all three. Loading uses skeletons that match final layout; empty
states explain the next action; errors are inline and non-destructive.

## Accessibility

- Landmarks: `header`, `nav[aria-label]`, `main`, `footer`.
- Focus: 2px brand-tinted ring via `:focus-visible`.
- Colour contrast: ink‑900/700 on white and white on `brand-deep` meet AA.
- Status conveyed by text + tone, never tone alone.
